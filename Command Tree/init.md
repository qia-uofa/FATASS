# `init`

## Syntax

```text
>>> init
```

Takes no arguments. Operates on the current `agent.topology` (see
`../agent.md`) — the root the very first time it's ever run (before any
`cd`), or whichever Topology `cd` last left `agent.topology` pointing at
otherwise. `init` is the one command allowed to run before
`agent.topology` resolves to anything real: on a brand new working
directory, nothing on disk backs the root yet, and this command's first
two steps are exactly what create that backing (see `../agent.md`).
Every other command assumes `agent.topology` is already a real, loadable
Topology instance by the time it runs.

## Behavior

1. If `agent.topology` is still the (as yet unbacked) root and
   `./Topology` doesn't exist yet, creates it.
2. If `./.class/` (sibling to `./Topology`, at the outer repo's own
   root — see `../Node/topology.md`) doesn't have its own `topology.py`
   yet, copies it in — along with the shadow `agent.py` module every
   `.class/` carries (see `../Node/class.md`) — from the hardcoded
   templates shipped inside the generated `Agent/` package. This is what
   makes the root a real, loadable `Topology` instance (reserved class
   name `topology`) rather than a plain directory `agent.topology` can't
   yet actually instantiate. Not applicable to any other
   `agent.topology`: every topology node besides the root already has a
   proper `.class/`, generated by `create -t` when it was made (see
   `create.md`) — there's no hardcoded template to copy for those, and no
   bootstrapping gap to close, since `cd` (see `cd.md`) can only ever
   move `agent.topology` to a topology node that already loaded
   successfully.
3. Scans `agent.topology.topology_path` to detect its existing child
   Nodes — both plain Nodes and topology nodes (see `../Node/topology.md`).
   A topology node's own nested `Topology/` is not descended into here;
   each nested Topology only gets scanned by `cd`-ing into it (see
   `cd.md`) and running `init` again there, if wanted.
4. Diagnoses each detected Node's `.class/` definition — e.g. missing or
   malformed class file, class name not matching the Node's folder name,
   constructor issues, and the like.
5. If any issues are found, starts a dialogue with the user to resolve
   them before continuing.
6. Once the Topology is clean, enters a dialogue to suggest new Nodes to
   create or other follow-up actions to take.
